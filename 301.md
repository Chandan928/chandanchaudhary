# Task: Force 301 Redirects — All URL Variants to Canonical Domain

## Objective
Ensure all four URL variants permanently redirect (301) to the single canonical domain: https://chandanchaudhary.com/

The four variants that must all resolve correctly:
- http://chandanchaudhary.com/ → 301 → https://chandanchaudhary.com/
- https://chandanchaudhary.com/ → 200 (this is the canonical — no redirect needed)
- https://www.chandanchaudhary.com/ → 301 → https://chandanchaudhary.com/
- http://www.chandanchaudhary.com/ → 301 → https://chandanchaudhary.com/

This applies to ALL paths, not just the homepage. Any path on www or http must redirect to the https non-www equivalent:
- http://chandanchaudhary.com/services/seo → 301 → https://chandanchaudhary.com/services/seo
- https://www.chandanchaudhary.com/blog → 301 → https://chandanchaudhary.com/blog
- etc.

## Fix 1 — Add Redirects to vercel.json

Open `vercel.json`. Add a `redirects` array. The http → https redirect is handled automatically by Vercel (it enforces HTTPS for all custom domains by default). The www → non-www redirect must be explicitly configured.

Add this to `vercel.json` — merge it carefully with the existing content, do not remove any existing keys (headers, regions, etc.):

```json
{
  "redirects": [
    {
      "source": "/:path*",
      "has": [
        {
          "type": "host",
          "value": "www.chandanchaudhary.com"
        }
      ],
      "destination": "https://chandanchaudhary.com/:path*",
      "permanent": true
    }
  ]
}
```

This single rule handles:
- https://www.chandanchaudhary.com/ → 301 → https://chandanchaudhary.com/
- https://www.chandanchaudhary.com/services/seo → 301 → https://chandanchaudhary.com/services/seo
- https://www.chandanchaudhary.com/any/deep/path → 301 → https://chandanchaudhary.com/any/deep/path

The `/:path*` wildcard captures everything including the root path and all subpaths.
The `permanent: true` flag generates a 301 (permanent redirect) not a 302 (temporary).
The `has` condition scopes the rule only to the www host — it does not affect the canonical domain.

Important: if `vercel.json` already has a `redirects` array, append this object to it — do not replace the existing redirects array entirely.

## Fix 2 — Add Redirect in next.config.ts as Backup

Open `next.config.ts`. Add a `redirects` async function inside the Next.js config as a belt-and-suspenders backup. This catches the www → non-www case at the Next.js layer in case the Vercel layer is bypassed:

```ts
async redirects() {
  return [
    {
      source: '/:path*',
      has: [
        {
          type: 'host',
          value: 'www.chandanchaudhary.com',
        },
      ],
      destination: 'https://chandanchaudhary.com/:path*',
      permanent: true,
    },
  ]
},
```

Add this inside the existing `nextConfig` object. If a `redirects` function already exists, append the new rule to its return array — do not replace existing redirects.

Important: the www DNS issue (CNAME record in GoDaddy) must also be fixed separately for the www redirect to work. If www.chandanchaudhary.com still returns a DNS error after this deploy, the CNAME record `www → cname.vercel-dns.com` is missing in GoDaddy DNS settings and must be added manually. The code changes in this task will be ready and waiting — they just need DNS to resolve first.
